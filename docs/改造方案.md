## 0. 一页结论

1. **代码基线**：用 upstream `velodb-mcp-server` v0.2.6 原样 vendoring，叠加一组**最小补丁**（约 10 处，见 §5），不再沿用旧 `doris-mcp-agentcore` 的代码，只复用它的**部署流程、agentcore.json 结构、VPC endpoint/排障经验和脚本**。
2. **托管**：新版 `@aws/agentcore` CLI，**CodeZip + Python 3.12（ARM64）+ VPC 模式**，Runtime 鉴权 **AWS_IAM**，Doris 走私网 `172.31.25.143:9030/8030`。
3. **鉴权简化**：原方案的"双 Cognito 池"改为 **单 Cognito 池（Quick→Gateway）+ Gateway→Runtime 用 IAM SigV4**（📄 Gateway 文档明确 Runtime 支持 IAM 出站）。少一套 OAuth、少一个 AgentCore Identity 凭证提供者。
4. **Quick 桌面版集成（新硬性要求）**：
   - **主路径**：Cloud Connector（MCP + OAuth）→ AgentCore Gateway。与官方博客同路径，桌面/Web/移动端通用，token 由 Quick 自动续期。
   - **备份路径**：桌面版 Local（stdio）连接器 → `mcp-proxy-for-aws`（本机 AWS 凭证 SigV4）→ 直连 Runtime。不依赖 Cognito、不受订阅层级限制，同一份配置可 Import 进 Claude Code（原方案"路线 2"）。
5. **Skills**：桌面版**原生支持 `SKILL.md`**（📄），因此 apache/doris-skills 直接"From folder"导入，再加一个我们自写的 **`doris-mcp-adapter` skill**，把 skill 里的 `doriscli` 调用翻译成 MCP 工具调用。这替代了原方案"把 skill 逻辑提炼进 agent 指令"的做法。
6. **Profile 补丁需要重写**：对 Doris 4.1.4 实测发现 `profile.py` 有 6 处与真实 API 行为不符（HTTP 永远 200、非 admin 查不到 `query_info`、字段名不同、profile 体积 100–200 KB 等），见 §4.1 与 §5.3。
7. **需要你拍板的 8 个决策**见 §12，其中 **D2（Quick 订阅层级）** 会直接决定主路径能否走通。

## 1. 目标与范围

**目标**：在 Amazon Quick **桌面版**里，用一个"Doris 专家"对话入口，基于**真实 Doris 集群（电商演示库 `ecom`）**完成：
- 语义层问答（GMV、订单数、客单价…按渠道/月份/区域）；
- 业务排查（第 5 幕：退款率异常 → 差评分词 → 物流瓶颈）；
- **Track A 诊断**：慢查询 → 自动抓 profile → `doris-profile-reader` / `doris-debug` 解读（依赖 profile 工具）；
- **Track B 设计评审**：读真实 DDL/分区/倾斜 → `doris-best-practices` / `doris-architecture-advisor` 给出推荐 DDL → **人工执行**。

**不在范围**：MCP 写路径（DDL/DML 仍由人执行）、多用户 Doris 身份透传、生产级高可用、VeloDB Cloud。

## 4. 已核实事实（本次只读验证）

### 4.1 Doris 4.1.4 profile API 实测（用只读账号 `demo_ro` 和 root）✅

| 验证项 | 实测结果 | 对 `profile.py` 的影响 |
|---|---|---|
| 错误状态码 | 密码错误返回 **HTTP 200**，body `{"code":401,"msg":"Unauthorized"}`；找不到 profile 返回 **HTTP 200**，`{"code":0,"data":{}}` | 按 HTTP status 判 401/404 的分支**永远不会触发**，必须判 body `code` / `data` |
| `/rest/v2/manager/query/query_info` | **非 admin 永远返回空 rows**（连自己的查询也看不到）；root 可见全部 | `list_recent_queries` 用服务账号时**必然为空** → 改用 `/rest/v1/query_profile` |
| `/rest/v1/query_profile` | 非 admin 可列出**所有用户**的已采集 profile（含 SQL 文本） | 可用；需加可见范围控制（决策 D4） |
| `/rest/v2/manager/query/profile/text/<qid>` | 只能取**自己的** profile，别人的返回 `data:{}`；文本在 `data.profile` | 字段是 `data.profile`，不是 `data` |
| `/api/profile/text?query_id=<qid>` | 返回纯文本，**不区分用户**；非法 id 返回 `code:500 "Invalid profile id"` | 作为跨用户回退 |
| 列名字段 | v2 返回 `columnNames`（驼峰） | `profile.py` 读的是 `column_names`，会得到 None |
| profile 体积 | 简单查询 **114 KB**，按天 COUNT(DISTINCT) **190 KB** | 直接返回会撑爆上下文 → 需要 summary 模式 + 截断 |
| profile 开关 | 全局 `enable_profile=false`，`auto_profile_threshold_ms=-1` | 默认 MCP 发起的查询**没有 profile** |
| 通过 MCP 开 profile | MCP 的 SQL 校验器**拒绝 `SET`**，但**放行** `SELECT /*+SET_VAR(enable_profile=true)*/ ...`；Doris 实测该 hint 能生成 profile；`execute_query` 原样透传 SQL | **不改 Doris 全局配置**，也能"带 profile 执行" |
| 错误码 | upstream `ErrorCode` 里**没有** `AUTH_FAILED` / `INVALID_ARGUMENT` | 改为 `UNAUTHENTICATED` / `INVALID_PARAMS`，否则 import 期 AttributeError |
| 依赖 | upstream 已依赖 `httpx`，没有 `aiohttp` | 改用 httpx，不新增依赖 |

### 4.2 Doris 权限与语义层 ✅
- `demo_ro` 只有 `SELECT` on `ecom` / `information_schema` / `mysql`。
- upstream 语义层把模型存在 Doris 的 `system_mcp` 库里，并在 `discover_workspaces()` 中执行 `CREATE DATABASE IF NOT EXISTS system_mcp`。**实测：Doris 在库已存在时仍会先校验 CREATE 权限**（`demo_ro` 执行 `CREATE DATABASE IF NOT EXISTS ecom` 报 Access denied）→ 纯只读账号会让语义层启动失败，必须处理（§6.1）。
- 发布语义模型时 upstream 会执行 `GRANT SELECT_PRIV ... TO '%'`，需要 admin → **模型发布走一次性本地 admin 流程**，Runtime 上不做（§6.3）。

### 4.3 AWS 网络 ✅ / 📄
- 账号 `890717383483`，default VPC `vpc-0b806cad7faf55718`：**无 NAT、无任何 VPC endpoint**。
- 📄 AgentCore VPC 模式在 us-east-1 支持的 AZ：**use1-az1 / use1-az2 / use1-az4**。Doris 所在子网 `subnet-0a06e314475c5d116` 是 **use1-az4**，受支持，无需迁移。
- Runtime 子网选择：`subnet-0a06e314475c5d116`(az4，与 Doris 同 AZ)、`subnet-065f33a1a5f2ac3ff`(az1)、`subnet-01c473181df2246e4`(az2)。
- 📄 ENI 只有私网 IP，放在"公有子网"也**不能**出公网 → 必须建 VPC endpoint：S3 Gateway（CodeZip 拉包）+ `logs`；我们还要 `secretsmanager`。
- Doris 私网 IP 在 EC2 stop/start 后不变（公网 IP 会变），**对 Runtime 无影响**。

### 4.4 Quick 桌面版 📄
- 2026-04-28 预览，**2026-09-09 GA**（macOS 12+ Apple Silicon / Windows 10 x64，含 us-east-1）。
- 连接器两类：
  - **Cloud Connector**：与 Web 版 Connectors → MCP 是同一对象，桌面/Web/移动端通用。仅支持远程 MCP，优先 streamable HTTP；鉴权三选一：User auth（OAuth 授权码 + PKCE S256 + RFC 8707）、Service auth（client credentials）、无鉴权；按 RFC 9728 发现；Cognito 不支持 DCR，需手填 Client ID/Secret。**MCP integration 文档写明前提是 "Amazon Quick Enterprise subscription"**（原方案写 Author+，需确认，D2）。
  - **Local connector**（仅桌面，配置存在 `~/.quickwork/`）：Local = stdio 命令；Remote = URL + 静态 Header（可存系统钥匙串）；Import = 从 Kiro / Claude Code 等配置文件导入。**未见 OAuth 支持**，静态 Bearer 会随 Cognito token 过期而失效。
- 限制：MCP 单次操作**固定 60 s 超时**，超时报 HTTP 424；单连接最多 100 个工具；工具 inputSchema 需符合 JSON Schema Draft 7+；自定义连接器改了工具后要手动 **Sync**（会触发重新授权），**新同步的工具默认禁用**；桌面单次最多 20 个工具并发；agent 指令最长 5 万字符。
- **Skills（桌面）**：文件夹 + `SKILL.md`（+ 参考文件/脚本），支持 From folder / .md / .zip 导入，单个 ≤ 6 MB；按 description 发现、激活时再读全文，工具从已连接的 connector 解析。

### 4.5 AgentCore Gateway 📄
- MCP server target 出站鉴权支持：无 / OAuth（2LO、3LO、token exchange）/ **IAM SigV4**（`IamCredentialProvider`，服务名 `bedrock-agentcore`）/ API key。
- 支持的 MCP 协议版本：2026-07-28、2025-11-25、2025-06-18、2025-03-26。
- DEFAULT listing 模式下，工具变更后要调 `SynchronizeGatewayTargets`；对 Runtime 目标建议开 MCP sessions，或在 target 的 `metadataConfiguration` 放行 `Mcp-Session-Id` 以减少重复 initialize。

### 5.3 Profile 工具重写要点（相对 `prepare/profile.py`）

```text
list_recent_queries(limit=20, user=None, sql_contains=None)
  → GET /rest/v1/query_profile（非 admin 可用；只列出已采集 profile 的查询）
  → 按 user / sql_contains 过滤后取前 limit 条；返回 query_id、user、db、耗时、状态、SQL 前 200 字
  → 如果服务账号是 admin，再合并 v2 query_info（可见运行中的查询）

get_query_profile(query_id, mode="summary", max_chars=20000)
  → 校验 query_id 格式：^[0-9a-f]{16}-[0-9a-f]{16}$（防止路径注入）
  → 先调 v2 /rest/v2/manager/query/profile/text/{id}，取 data.profile
  → 若返回 data == {}（别人的查询）→ 回退 GET /api/profile/text?query_id=
  → 若仍找不到 → success(profile_found=false, hint=...)，作为结构化证据返回（保留原设计）
  → mode=summary：保留 Summary / Execution Summary / 各 Fragment 与 Operator 的耗时和行数计数器，
                   去掉 "N/A" 行，截断到 max_chars；mode=full：原文截断到 max_chars
公共：httpx.AsyncClient；按 body.code 判定（401 → UNAUTHENTICATED，其它非 0 → CONNECTION_ERROR）；
      凭证使用服务账号（P-06）
```

**"带 profile 执行 SQL"（原 gap 表最后一行）**：不新增工具。在 adapter skill 里约定：
`execute_query("SELECT /*+SET_VAR(enable_profile=true)*/ /* trace:<随机串> */ ...")` → `list_recent_queries(sql_contains="<随机串>")` 拿到 query_id → `get_query_profile(query_id)`。用 trace 注释定位 query_id，可以避开连接池导致 `LAST_QUERY_ID()` 不在同一连接的问题（P1 实测确认）。

## 6. Doris 侧准备

### 6.1 服务账号 `mcp_svc`
```sql
-- doris/01_mcp_user.sql（由 root 执行；密码从 Secrets Manager 生成后手工带入，不落文件）
CREATE USER 'mcp_svc'@'%' IDENTIFIED BY '<from-secret>';
GRANT SELECT_PRIV ON internal.ecom.* TO 'mcp_svc'@'%';
GRANT SELECT_PRIV, CREATE_PRIV ON internal.system_mcp.* TO 'mcp_svc'@'%';  -- CREATE 只为通过 CREATE DATABASE IF NOT EXISTS
```
- 不授予 ADMIN / LOAD / ALTER / DROP。能访问哪些数据由 Doris 权限决定，MCP 的 SQL 校验器是第二道防线。
- 用 `'%'` 的原因：P1 需要从本机（13.125.9.110）联调；网络边界由 SG 控制（只有 /32 和 Runtime SG 两个来源）。P3 之后可以收紧为 `'172.31.%'`（D6）。
- 备选：不给 `CREATE_PRIV`，改为给 `discover_workspaces()` 打一行补丁（库已存在时跳过 CREATE）。

### 6.2 Profile 策略
- **推荐（D5）：不改全局配置**，只用 `SET_VAR` hint 按需采集（§5.3）。
- 备选：`SET GLOBAL enable_profile=true; SET GLOBAL auto_profile_threshold_ms=1000;`，自动采集慢查询。单节点演示库可以接受，但会影响所有会话。

### 6.3 语义层：`ecom` workspace

## 8. Quick 桌面版集成

### 8.1 主路径 ①：Cloud Connector → Gateway
1. 桌面版 **Customize → Connectors → Create → Cloud Connector → MCP**（在 Web 端 Connectors → MCP 创建效果相同，创建后三端都能用）。
2. URL：`https://<gateway-id>.gateway.bedrock-agentcore.us-east-1.amazonaws.com/mcp`
3. 鉴权（D3）：
   - **User authentication（推荐，与博客一致）**：Client ID/Secret 填 client A；Token URL `https://<poolIdWithoutUnderscore>.auth.us-east-1.amazoncognito.com/oauth2/token`；Authorize URL 把末尾换成 `/oauth2/authorize`。演示者用 Cognito 账号登录一次即可。
   - **Service authentication**：填 client B，不需要用户登录；所有使用者共享一个机器身份。
4. 创建后**逐个启用工具**（新工具默认禁用）；权限建议：只读工具设为 Always Allow，`execute_query` 设为 Ask Each Time（D7）。
5. 工具有变更时：Gateway `SynchronizeGatewayTargets`，然后在 Quick 连接器详情页点 **Sync**（会重新授权）。

### 8.2 备份路径 ②：桌面版 Local stdio → Runtime（SigV4）
桌面版 **Customize → Connectors → Create → MCP server → Local**，或者粘贴下面的 JSON：
```json
{
  "mcpServers": {
    "doris-agentcore": {
      "command": "uvx",
      "args": ["mcp-proxy-for-aws@latest",
               "https://bedrock-agentcore.us-east-1.amazonaws.com/runtimes/<URL编码的RuntimeARN>/invocations?qualifier=DEFAULT"],
      "env": { "AWS_PROFILE": "doris-demo", "AWS_REGION": "us-east-1" }
    }
  }
}
```
- ❓ `mcp-proxy-for-aws` 的参数名以 P0 实测为准。
- 优点：不经过 Cognito / Gateway，token 不会过期，不受 Cloud Connector 订阅门槛限制；同一份 JSON 可以 Import 进 Claude Code，做 skill 原生用法的对照演示（原"路线 2"）。
- 缺点：本机要有 AWS 凭证（最小 IAM：`bedrock-agentcore:InvokeAgentRuntime` 限定该 ARN）；只在本机开机时可用。
- 再备选：沿用旧仓库 `mcp-token-proxy.py`（127.0.0.1:3333）→ Gateway（client B），桌面版 Remote 填 `http://127.0.0.1:3333/mcp`。
- **不推荐**：Remote + 静态 Bearer（Cognito access token 最长 1 天）。

### 8.3 "Doris 专家" Agent
- 在桌面版创建自定义 Agent，关联 ① 或 ② 的连接器和 §9 的 skills。
- 指令（远低于 5 万字符上限）只写三件事：角色（基于真实 ecom 集群的 Doris 专家）、硬约束（证据优先、只读、DDL 只给出不执行）、演示口径（中秋节 2026-09-25 12:00 的业务设定）。
- skill 选择交给 Quick 按 description 自动匹配。
